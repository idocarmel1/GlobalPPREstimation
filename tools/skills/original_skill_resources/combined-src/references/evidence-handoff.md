# Evidence, execution and adoption contract

Read this contract with the requested stage reference. It governs evidence and handoff completeness, not model selection or scientific algorithms. It does not require a new transformation-chain archive, balanced-state retention, a different calculator state, or numerical repairs. Preserve existing source evidence and ordinary input/settings provenance.

## Explain the run and respect existing authorization

Before a fresh scientific run, finish independent review of saved evidence and explain the unresolved gap, why retained evidence cannot answer it, the smallest sufficient stages, exact model/variant and input identities, constructor and method settings, expected artifacts, estimated runtime/output bounds, and files/results potentially affected. Obtain explicit confirmation before executing an unapproved run. Existing explicit authorization covers the stated scope: explain the concrete setup, then proceed without asking again. A request to review evidence or update a skill alone is not run authorization.

Additional models, expanded stages, new assumptions, numerical repairs and adoption/publication require separately explained confirmation unless already explicitly authorized. Do not use a broad exporter or Monte Carlo inventory to fill missing documentation. Saved-evidence review and report arithmetic do not require a scientific rerun. Record a blocked stage honestly and continue independent authorized work.

## Portable evidence inventory

The portability purpose is that another user can clone/download the repository into a different folder and follow its evidence links. Apply the [validation guide's link rules](../../../../templates/Model_validation_template_instructions.md#links-output-and-verification) to current Word reports, Excel appendices and supporting documents as well as inventory paths. Local hyperlinks resolve from their containing file; preserve public URLs and internal anchors, reject machine-specific Hyperlink Base values, and verify stored targets after relocation. Rebase links when moving deliverables; preserve frozen baseline snapshots.

Keep a versioned evidence directory with an index containing `schema_version`, `run_id`, region/model/variant IDs, source identity, computational-input identity, methods/options, and artifact availability. Each artifact has a role, portable relative path, SHA-256, and availability (`present`, `missing`, `failed`, or `inapplicable`). Missing/failed/inapplicable entries need a reason and acquisition status; never omit them to imply completeness. Links may point into retained regional or research evidence; temporary, ignored-runtime and machine-specific absolute links are insufficient for permanent handoff.

Inventory the applicable source documents and locators, extraction tables/JSON and round-trip evidence, taxonomy, mapping/assumption evidence, diagnostic returns/matrices/coefficient tables, arithmetic context, comparison results and adoption checks. Link existing reconstruction evidence when relevant; this contract adds no complete transformation-chain retention requirement. Overview and Project.xlsx remain configuration/selection authorities. The index authenticates evidence and must not become another project status/configuration source.

Before claiming completion, reopen every listed present file, check hashes and required identities, check required roles for each applicable stage, and retain a machine-readable completeness result with missing roles and reconciliation failures. Include partial/failed runs. A valid index with missing required evidence is an incomplete scientific handoff.

Run `python <skill-root>/scripts/check_evidence.py <evidence-index.json> --output <completeness.json>` for inventory integrity. The checker expects schema version 1, `required_roles` naming the applicable required artifacts and optional `reconciliation` name-to-Boolean results from the stage's numerical checks. It verifies files/hashes and declared checks without invoking a calculator. It cannot decide which scientific stages apply or establish that a claimed reconciliation is correct; verify those independently. Test the checker with `python <skill-root>/scripts/test_check_evidence.py`.

## Diagnostic evidence from one execution

For every requested option, retain the losslessly serialized full diagnostic return and coefficients from the same call (`return_sppr=True` where supported). Retain every returned matrix, including the group-by-basal-source contribution matrix when supplied. Scalar formulations must explicitly say decomposition is unavailable; never invent source columns.

Retain ordered row/column IDs and names, orientation, units, source-scope definitions, synthetic-group flags, and separate null/NaN/positive-infinity/negative-infinity masks. Preserve all retained groups, including unfished groups. Serialization must preserve types/axes and distinguish unknown from zero; spreadsheet display rounding is not lossless storage.

Record method/options, all effective settings and thresholds/tolerances, constructor identity, input and runtime/code identities/hashes, environment, timestamp, exception/timeout details, overall/component grades and strict flags. Ordinary runtime provenance identifies the executed configuration; no new state-selection or balanced-state publication requirement follows. Retain rho_living, named detritus-pool SPPR and recycling b's definition/applicability. TE's b=0 convention does not establish absence of physical recycling.

Create a negative-entry table keyed by method, matrix, source column ID/name and recipient group ID/name, with the actual value and comparison tolerance. It is a convenience view, never a replacement for the matrix. Verify null/nonfinite masks, unique axes, dimensions and scope membership after reopening. Recompute scope sums from the retained contribution matrix and reconcile them with saved coefficients and diagnostic summaries using declared tolerances; preserve and explain disagreements. Aggregate-only exports are explicitly incomplete for formulations returning a source matrix.

## Source, geography and arithmetic context

Retain citation/DOI/accession, exact source version/hash, printed and PDF page/table/cell locators, competing table versions and selection rationale. Distinguish publication date, modeled period and catch year. Keep the selected-model study figure/caption and region-boundary identity, period applicability, area/polygon/trace evidence where available. For overlap, identify method, landmarks, uncertainty and both denominators: A = overlap/region and B = overlap/study area. A picture or filename does not prove measured coverage.

Freeze the assessed catch universe, including zero rows, exact taxon join keys, available versus assessed catch bases, TL/coefficient source/snapshot, method/TE, native/displayed units, missing masks and unresolved inclusion rule. Retain unrounded numerators/denominators and source-to-result reconciliation for the chosen year/basis. Wet-weight PPR converts to carbon by division by nine exactly once. Unknown coefficients stay unknown even for zero catch, but the annual PPR contribution of genuine recorded zero catch is zero. Positive catch with an unknown coefficient has unknown PPR; do not confuse the coefficient availability mask with the annual-contribution availability mask. These are evidence extracts of authoritative tables, not replacement configuration.

## Membership, allocation and assumptions

Preserve the three-column Taxonomy.xlsx contract. Use a companion evidence table for exact taxon/group IDs, source spelling, accepted synonym/authority ID where verified, exhaustive versus representative membership, residual-category meaning, habitat/size/stage bounds and units, source page/table/cell, period/area/basis, all candidates (including zero weights), and conflicts.

For each mapping record membership rule/confidence/evidence separately from allocation rule/confidence/evidence; retain overall review category/rationale, adopted decision/version and prior decision. Use the rule definitions in the [validation template guide](../../../../templates/Model_validation_template_instructions.md), not a duplicated rule system. Keep an independent `assumed` flag and assumption type; High/Medium/Low/Very low/Unresolved must not erase assumption-dependent coverage. Unknown evidence fields remain explicitly unavailable.

Retain observed caught-mass numerators/denominators and conversions, or exact source/raw/effective/loaded catch values and proxy formula when applicable. A search record includes query/date/URL, material actually read, version or retained excerpt, applicability and adoption/rejection reason. Distinguish full text, snippets and inaccessible pages. Numerically valid weights do not establish membership or geographic applicability.

The approved unresolved-taxon fallback establishes eligible groups from taxonomy, ecology and exact model definitions, then uses complete model catch proportions first and model biomass proportions only when catch is unusable. Both routes are explicitly assumed Medium allocation confidence; assess membership uncertainty separately for the combined category. Record candidate inclusion/exclusion, source fields, values, units, valid zeros, totals, proportions, rejected catch attempt where applicable, and transfer assumptions. Prefer near-complete catch coverage under the validation guide’s M10/M11 Very low broad-category and closest-analogue rules when strict source membership is uncertain. Use applicable direct geographic source allocation at High confidence before the proxy hierarchy; source geographic overlap alone is not catch composition. If the proxy hierarchy fails, a justified W11 Very low allocation is permitted. Reserve unresolved groups/weights for cases where no meaningful choice or numerical assumption can be justified. Preserve uncertainty explicitly and follow the validation guide for all rules.

## Review-to-adoption completion gate

A final validation report must agree with adopted regional data and the map. Report-only reclassification is not completed validation. Keep a keyed discrepancy ledger with old/proposed group, weight and confidence, rule/evidence, decision, affected catch/PPR basis and adoption state. Distinguish confidence-only corrections from numerical weight changes. Classic-PPR exposure is not a predicted GE/TE change.

After authorized adoption, reconcile Matching and Allocation assumptions; recalculate only dependent regional outputs as needed, retaining existing group SPPR when its input/configuration is unchanged. Propagate affected records to Project.xlsx and rebuild/verify map, trends and archive. Use one adoption/run identity across evidence and outputs. Compare selected IDs, mappings, confidence/assumption labels, method restrictions, year/basis/scope/treatment, coverage, totals and carbon conversion. Check generated payloads and the visible browser, including remembered selections. Derive the separate Word coverage section and linked seven-column Excel appendix from adopted rows. Excel has frozen headers, filters, descending unrounded simple-chain PPR order with unavailable values last, and a descriptive Sources sheet. In Word use separate group-assignment and allocation tables with exact columns Plain-language rule | Confidence | PPR percentage. Each partitions the same entire known simple-chain PPR universe once, including unresolved or not-applicable records; distinguish component confidence from weakest-component overall confidence and do not add the tables together. Use full descriptions and nearby descriptive source links, without M/W codes or numbered-reference shorthand. Reconcile the actual map controls, payload, unrounded result and visible rounding with this denominator; workbook annual agreement alone is insufficient. Until alignment is authorized and verified, label the report a **pending-alignment draft** and separate proposed from adopted figures.

Keep validation prose limited to scientific findings, assumptions and evidence: list unresolved taxa/reasons and compactly flag Very low decisions and their coverage share. Put execution, approval, integration, hash and test details in supporting evidence.

Preserve researcher originals and the entire manually maintained SPPR calculation row, formatting and links, together with other manual rows, in derivative reports. Never attach to the user's active Word instance. Respect excluded basenames before reading, hashing or copying.

## Comparing skill versions

Preserve checkpoint and old-skill baselines before editing. Explain model selection, exact settings, matched baseline and isolated outputs before the authorized runs. Reuse source documents as evidence, but independently perform each required applicable stage; extraction replay or diagnostic-only execution is not a whole-workflow test. Record every stage as performed, blocked, or genuinely inapplicable with evidence and reasons.

Compare extraction fields, diets, group identities, taxonomy, mappings/weights, requested and previously adopted applicable methods, diagnostics, coverage and regional totals on matched inputs, year/basis/scopes/conversions. Declare exact equality separately from numerical tolerance, with maximum absolute/relative differences and changed group/taxon keys. Do not loosen tolerances, copy old answers into a new run, or adopt scientifically changed interpretations merely to finish. New evidence/timestamps need not be byte-identical. An incomplete stage or unresolved difference prevents a claim of full scientific equivalence.

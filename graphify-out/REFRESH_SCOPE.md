This refresh indexes the project's architecture and reviewed scientific evidence. The explicit `.graphifyignore` keeps the corpus below 500 files and two million words. The portable manifest records the complete selected corpus using repository-relative paths and content hashes.

Included: the three project source trees and their tests; integration tools and tests; current project documentation; reviewed mapping notes, model profiles and work orders; the isolated new-paper validation's original reproduction code and reports; the durable independent Guinea comparison reports; canonical Claude extraction and mapping resources; the combined router and taxonomy source; both Claude and Codex skill entry points; and Codex workflow/interface wrappers. Copied implementation resources are represented by their canonical source and the distribution documentation.

Excluded: generated spreadsheets, CSV/JSON numeric data, images, PDFs, raw paper archives, downloaded research, generated atlas HTML, notebook exports, packages, caches, scratch work, personal settings, obsolete model catalogs and duplicate evaluation/tool/skill copies. These artifacts remain in the project; the graph links their governing code and reviewed conclusions rather than converting thousands of regenerated cells or pages into duplicate text.

Structural extraction parses code without executing any project algorithm. Changed documents are read by host semantic-extraction agents using the graphify confidence rubric. Unchanged graph entities and their relationships are retained. Old source paths are normalized; deleted, excluded and changed sources are pruned from the old graph before fresh extraction is merged. Existing hyperedges and original directional edge endpoints are preserved. Fuzzy entity deduplication is disabled to avoid merging similarly named symbols from different files.

The installed graphify version prunes after merging when `build_merge(prune_sources=...)` is used, which would also discard newly extracted nodes from changed files. The refresh helper therefore filters only the old graph first and then uses `build_merge` on that retained graph. This is a graph-maintenance workaround; no PPR algorithm or Jensen calculation is changed.

Semantic token usage and monetary cost are unavailable because the host subagent tool exposes no usage totals. Placeholder zeros required by the extraction schema are not reported as measured usage or zero cost. Historical cost records are preserved but are not independently verified.

Graph validation checks endpoint integrity, portable and existing source paths, removal of personal settings, all six skill entry points, the final integration and independent-comparison reports, and the requested PPR-scope, model-health, provenance and Jensen concepts. Presence in the graph is a retrieval check; it is not proof of scientific validity or numerical correctness.


The completed refresh contains 2,082 nodes, 3,256 edges, 13 hyperedges and 143 named communities across all 229 selected files. It preserves 827 unchanged nodes and 1,323 unchanged-source edges, including ten links to refreshed nodes. Independent comparison checked every retained edge attribute and original direction. Fifty-one old edges were pruned because an endpoint no longer exists in the selected final graph. The final incremental check reports zero changed and zero deleted files.

They are source-attributed review questions, not simultaneous confirmed scientific claims. Existing source and mapping uncertainties remain visible.
